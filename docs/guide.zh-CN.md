# Relic 完整使用指南

[English](guide.en.md) · [Windows](windows.zh-CN.md) · [macOS](macos.zh-CN.md) · [工具参考](reference.zh-CN.md)

## 1. 选择版本

**Claude 版**是较精简的 Claude Code 专用实现，支持一个负责人带多个 Claude Code 子智能体，也支持多个平级会话。**Codex / GPT 版**使用 Codex 的真实会话身份，可选择同一根聊天下的原生子智能体，或多个独立桌面聊天。**Bridge 版**让 Claude Code 和 Codex 加入同一个本地组织，提供成员面板、会话配置、消息、有界自动唤醒和经过授权的轨迹导出。

这里的“GPT 版”指 **Codex 编程会话**。普通 ChatGPT 网页聊天不会因为安装本包而获得本地 MCP 工具。Bridge 另有 ChatGPT 聊天席位功能，但需要人工转发回复，并依赖 Windows 桌面通信。

同一个宿主只启用一套 Relic。Claude 和 Bridge 的插件都叫 `relic`，同时启用会造成工具名和 hooks 重复；Codex Organization 和 Bridge 也会注入不同的组织上下文。请在宿主插件管理器中停用不用的版本。独立 Codex 版与 Bridge 的数据结构、治理 API 不同，不能让它们直接共用同一个数据库文件。

## 2. 安装与检查

按 [Windows](windows.zh-CN.md) 或 [macOS](macos.zh-CN.md) 指南安装。安装器会在使用者电脑上解析 Python 和服务器路径，让 hooks 使用同一个解释器，再调用宿主官方插件 CLI。安装器不会替你登录、购买额度、批准 hooks、停用已有插件或修改组织数据。

解压目录需要长期保留：Codex MCP 配置会引用其中的服务器文件。移动后要从新位置重新配置和安装。`--configure-only` 只准备文件，不向宿主安装。Bridge 使用 `--host codex` 或 `--host claude` 可只安装一边；另一边随后安装相同的 Bridge 版本即可。

安装后开始新会话，在宿主插件设置中审阅并信任 hooks。hooks 不可用或未被信任时，共享工具可能仍能工作，但不能假定自动上下文注入和工具阻断已生效。先检查宿主实际加载的 MCP 工具列表，再用一个无害的小任务试用。

## 3. 创建第一个 Claude / Bridge 组织

在已启用插件的 Claude Code 会话中说：

> 用 Relic 建立一个两人组织，完成小型文档任务。我会给出任务和工作区边界。先创建组织，告诉我组织 ID，等另一名成员加入。

负责人调用 `create`，提供 `name`、`purpose`、`member`，可选 `role` 和治理方式 `governance`（`leader` 或 `peer`）。记下返回的 `org_id`。在第二个会话中说：

> 加入 Relic 组织 org_…，成员名 reviewer。读取当前组织状态，并与负责人协调。

使用 Bridge 时，第二个会话可以是 Codex。两边必须在同一台电脑上使用同一个 `RELIC_HOME`。Claude Code 工具通常以 `mcp__plugin_relic_org__*` 开头；Bridge 的 Codex 工具通常为 `mcp__relic_org__*`。具体显示前缀以宿主加载的工具列表为准。

Claude Code 的负责人加子智能体模式可以使用包内的 `relic:member` 定义。每个子成员需要实际组织 ID、成员名、任务和边界。不要伪造其他会话的 actor；身份由 hooks 或宿主元数据提供。

已有独立会话直接 `join` 最简单。Bridge 也会读取工作区的 `.relic-seat.json`：

```json
{"org":"org_actual_id","member":"reviewer","role":"review"}
```

填写真实返回的组织 ID。不要将席位文件复制到无关工作区。不同会话以同一个成员名加入表示更换该席位的载体，并不是新增两位成员。

## 4. 创建第一个 Codex 组织

安装独立 Codex 版后可以说：

> $relic-organization 使用原生子智能体为这个任务建立两位成员，当前聊天作为根。给成员不同职责，并核对真实宿主身份。

根会话先通过 `org_organize` 登记组建请求，再调用宿主真实 collaboration 工具创建子成员。子成员用自己的元数据加入。组织记录创建成功不等于已经创建了智能体。原生消息返回 outbox 路由，成员必须真正调用该宿主路由，并由收件人确认。若宿主不提供原生协作工具，则这种运行模式不可用。

独立桌面聊天模式下，请 `$relic-organization` 打开面板。选择已有聊天，或明确要求创建新聊天，指定负责人后启动。每个成员保留自己的工作区。创建聊天和发送消息遵循宿主授权与工具接口。远程主机和云端 ChatGPT 对话不在本机聊天索引中。

静默模式会等收件人空闲后批量投递消息，需要面板所提示的通知设置；插件不会悄悄修改全局通知偏好。逐条桌面模式按消息单独投递。原生子智能体组织不能直接切换成桌面执行模式。

## 5. 共同工作、episode 与持久协议

Relic 区分三类状态：

| 状态 | 示例 | 席位换人后保留？ |
| --- | --- | --- |
| 成员私有笔记 | 私人临时观察 | 不保留 |
| 共同工作 | 消息、版本化文档、任务、episode | 保留 |
| 组织协议 | 已采纳的共同约定与可执行规则 | 保留 |

需要多人依赖的接口和决定写入共享文档。更新时提供预期 revision，避免覆盖同伴刚完成的修改。任务应有负责人，标记完成时附提交、审阅文件或测试结果等具体证据。消息是持久通信记录，投递回执不是任务验收。

为一个有意义的协作单元打开 episode，以真实结果结束，再由每位参与者反思实际遇到的协调问题。同类问题反复出现时可以提议组织协议。插件不会预置业务协议，也不要求组织达到某个协议数量。

**弱协议**是共享指导。**强协议**额外提供明确可执行条件，作用于支持的工具调用。Claude / Bridge 支持 `deny`、`require_review`、`require_before`；独立 Codex 版使用 `deny`、`require_peer_review`。两套规则格式不能直接混用，详见 [工具参考](reference.zh-CN.md)。

协议例子包括按职责限制目录写入、对准确的发布命令要求同伴审核、要求最后一次修改后先通过测试。成员通过各版本的治理 API 提案、讨论和批准。提案不等于已生效的强制规则。修订和废止保留历史；使用记录应区分遵循、偏离和不适用。

hooks 只约束实际经过它的动作，不能当作操作系统隔离或对所有托管工具的全面控制。宿主沙箱和正常权限仍然适用。遇到不合理规则时，通过保持可达的治理工具缩小范围、修订或废止。

## 6. Bridge 面板与自动回合

在聊天中说“打开 Relic 面板”，或在源码仓库运行 `python scripts/open_panel.py --edition bridge`（macOS 使用 `python3`，单独 Bridge 下载包省略 `--edition`）。Tk 面板可创建组织、配置席位、选择已有会话、查看共同工作和更换成员载体。只有为成员选择 worktree 时才创建对应工作树。

每个席位可以选择宿主、工作目录、模型和权限。模型留空时使用宿主默认值。插件本身不直接调用模型 API；启动的模型回合消耗宿主账号额度或其配置的 API 计费。

配置过的席位，在组织启用自动唤醒后可因新消息启动额外回合。当前限制包括最多六跳自动消息链、编程席位两分钟间隔、每组织每小时最多三十次唤醒。回执不会递归唤醒发送者。在组织面板关闭自动唤醒即可停止这种行为。未配置的席位通过显式工具、hooks 或 `inbox` 接收消息。

Windows 桌面投递使用应用自己的工具管道。请求可能已经送达但未确认时保留 uncertain，不盲目重发。macOS 尚未实现这条 Bridge 通路：使用 CLI 持有的会话和显式 `inbox`；不要通过另一个写入者恢复已被桌面锁住的会话。macOS 面板“打开 CLI 会话”的便捷入口尚未认证，请自行在 Terminal 打开会话。

## 7. 聊天席位与轨迹访问

Bridge 的 Claude Chat 接入需要在 Claude Desktop 单独配置本地 MCP，安装 Code 插件不等于配置 Chat 页。该连接使用 `claude-chat:` actor 和最长 50 秒 inbox 等待；聊天需自己发起回合。

Windows ChatGPT 聊天席位可接收发到桌面聊天中的同伴消息，但回复需要本人复制后从讨论室转发，插件不能自动读到完整回复。这不是 ChatGPT 网页版的全自动集成，也不在 macOS 内测可用范围内。

成员请求另一位成员的轨迹时必须说明理由，并得到对方批准。读取自己席位前任的轨迹由人类决定。导出可能包含完整对话、工具记录和可归属该会话的记忆；默认脱敏不能保证去掉所有私人细节。不需要记忆时传 `memory:false`，共享前检查文件，并阅读 [隐私与数据](privacy.zh-CN.md)。

## 8. 数据、升级与卸载

| 版本 | 默认数据位置 | 自定义变量 |
| --- | --- | --- |
| Claude | `~/.claude/relic/relic.sqlite3` | `RELIC_HOME` |
| Codex / GPT | `~/.codex/relic-organization/organization.sqlite3` | `RELIC_ORG_HOME` |
| Bridge | `~/.relic/relic.sqlite3` | `RELIC_HOME` |

`~` 是当前系统账号的主目录。一个组织的所有成员必须使用同一台电脑上的同一个数据目录；不支持依靠网盘同步在多台电脑上并发共享数据库。

升级前先关闭自动唤醒和插件进程，再私下备份完整数据目录，包括可能存在的 SQLite WAL/SHM 文件，并保留旧插件包。将新版解压到准备长期保留的路径，在宿主管理器中将本地 marketplace 更新到该目录；若宿主提示名称重复，先移除旧 marketplace 注册再安装。运行新版安装器，重启宿主，按提示重新审阅 hooks。不要为了修安装错误而删除组织数据库。

回滚时，在进程已停止的条件下恢复旧插件与匹配的数据备份。卸载时在宿主插件管理器中移除该版本；数据和源码目录会保留，只有明确不再需要记录时才另行删除。本版不包含三种数据格式间的自动迁移。

## 9. 排错与反馈

源码仓库中运行 `python scripts/doctor.py --edition bridge`，单独下载包省略版本参数。它只报告本地依赖与路径存在性，不读取聊天内容，不启动模型回合。

| 现象 | 检查方向 |
| --- | --- |
| 找不到 Relic 工具 | 是否装对版本、是否新会话、解释器和脚本路径、宿主 MCP 日志 |
| 强规则从不阻断 | hooks 是否被信任和启用、规则是否 active、该工具是否经过 hook |
| 尚未加入组织 | 使用当前会话加入真实组织 ID，不覆盖其他成员身份 |
| 文档 revision 冲突 | 读取最新版，合并修改，再使用其 revision 写入 |
| 消息 pending | 收件人配置/空闲状态、投递模式、显式 inbox 或原生 outbox 路由 |
| 消息 uncertain | 先查收件人回执，再决定是否重试，可能已送达 |
| 面板打不开 | Tk 与图形显示是否可用，在 Terminal 启动查看错误 |
| Codex 桌面上下文过期 | 重开宿主，从实际 Codex 聊天再次调用面板 |
| macOS Bridge 无法唤醒桌面聊天 | 当前平台限制，使用 CLI 同伴或显式 inbox |

报告问题时附发布/组件版本、系统、Python 和宿主版本、失败步骤、预期行为及最小脱敏日志。不要默认上传真实组织数据库或完整轨迹。Codex 源码附带的 SCOPE / benchmark 模块属于实验性开发扩展，可能需要额外仓库或 Docker；日常组织不需要它们，本次内测发布也不据此宣称研究效果。

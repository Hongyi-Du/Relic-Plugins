# Privacy and local data

[中文](privacy.zh-CN.md)

Relic stores organization messages, documents, tasks, membership (including the seats each session holds), episodes, protocols, approval requests and runtime receipts locally in SQLite (`~/.relic/relic.sqlite3`). It may also save seat environment configuration and approved trajectory exports. These records can contain private work and credentials supplied by a user; keep their directories and backups private. Everything Relic keeps is under `~/.relic`, or under `RELIC_HOME` when it is set: the store, the App's files in `app/`, the ACP adapters in `acp/`, logs in `runs/`, the default folders of members added in the App in `workspaces/`, and trajectory exports in `trajectories/`.

The runtime does not contain its own model service, API key, analytics endpoint or hosted organization database. The plugin's MCP server and hooks call no model. When a member starts a turn, its host application receives the prompt and uses that account's normal provider, permissions and billing; members that run inside the Relic App are sessions of your own Claude Code or Codex and are no different. Shared messages become visible to the members addressed by the organization workflow. When you place an organization under another, members of the organizations above can also read its members, protocols, tasks, documents and recent messages. The local store is not an access-control boundary against another program running as the same operating-system user.

Trajectory access is a separate request/approval workflow. Approved exports may include full prompts, responses, tool arguments/results, reasoning records present in the source transcript, and session-attributable memory. Redaction is enabled by default, but personal text and unusual secrets may remain. Inspect an export before sending it outside the organization. `memory:false` excludes memory when making a request; never use `redact:false` casually.

Only session-associated Codex memory can be attributed to a requested session. Shared Claude project memory is not exported as if it belonged to one session. Replacing a seat retains shared organization records, while the previous carrier's private note state does not become the new carrier's notes.

The Relic App serves only this computer (127.0.0.1): a request must name the local address, and writes need a token that only the App's own page can read. It keeps your name, avatar, preferences (the language among them) and the results of Plain words and Digest in `~/.relic/app/`; when it opens in an Edge or Chrome window rather than as an installed application, that window's browser profile is in `~/.relic/app-window`. Plain words, Digest and automatic member names send the organization messages and member roles involved to your signed-in Claude Code (`claude -p`, no session saved; Sonnet for Plain words and Digest, Haiku for names), processed and billed under your Claude account as usual; to avoid this, leave both off in the group chat and turn off automatic names in Settings. The App downloads the ACP adapters from npm only when you install them under Settings → Harness connections. The file preview reads only members' working folders, files a member changed, and the Relic data folder. Voice input uses Microsoft Edge's online speech recognition.

Removing the plugin does not erase the database, transcripts, host sessions or exports. To discard records, stop Relic's processes, including the App's server, and explicitly remove the intended local data after backing up anything needed. Do not publish the data directory, `.relic-seat.json`, runtime receipts or entire transcripts in a GitHub issue. Report security-sensitive findings privately using the contact information on [Hongyi Du's website](https://hongyidu.ai).
